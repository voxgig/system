# Explanation: how the model wires the runtime

*Diátaxis: explanation — the ideas behind `@voxgig/system`.*

## Declare in the model, implement on disk, connect by name

A Voxgig system keeps three things separate:

- **The model** (`model/*.aontu` → `model.json`) declares *what exists*:
  entities, services, and the messages each service answers.
- **The file system** (`src/srv/<srv>/*.ts`) holds *how*: one action file
  per message.
- **`MakeSrv`** connects them at boot: for each model-declared message of
  a service, it derives the action file name from the message's last
  pattern pair (`save:item` → `save_item`) and registers the action with
  gubu-validated params from the model's `params` declaration.

The payoff: the model is a complete, machine-readable contract (used for
codegen, gateway routing, and the runtime-model-driven web UI), while
service code stays plain files with no registration boilerplate. A message
without an action file fails loudly at boot — the model and the code
cannot silently drift.

## Unification, not rewriting

The `add` commands never rewrite model files — they append jsonic blocks.
Aontu *unifies* all sources, so repeated or overlapping declarations
merge, and your hand formatting and comments survive tooling edits. This
is also why `add env web` can idempotently append service and message
declarations: unification makes re-declaration harmless, and the command
skips itself when `main.srv.auth` already exists.

## Local vs. Live

`Local` assembles every model-declared service into one Seneca instance
(in-memory store, in-process messages) — the whole system in one process
for development and tests. `Live` assembles the same services for a
deployed topology (e.g. one Lambda per service, generated by
`@voxgig/build`), where the same messages travel over transport instead.
Service code is identical in both; only the assembly differs. That is the
core microservices bet of Seneca: *transport independence* — pattern-based
messages don't care where the responder lives.

## Validation lives at the boundary

Message `params` from the model become [Gubu](https://github.com/gubujs/gubu)
shapes (`gubuify`). Objects are closed by default; the model marks open
objects explicitly (`'$$': 'Open'`). Validating at message entry keeps
action bodies free of defensive checks and makes the model the single
statement of each message's contract.
